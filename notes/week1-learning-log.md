## Key terms

- **Git:** A distributed version-control system that records changes to files over time.
- **GitHub:** A platform for hosting Git repositories and collaborating through branches, issues, pull requests, and reviews.
- **Repository (repo):** A project directory tracked by Git, including its files and commit history.
- **Clone:** Copy a remote repository to a local computer.
- **Remote:** A named reference to a repository hosted elsewhere, commonly called `origin`.
- **Working tree:** The files currently checked out on the local machine.
- **Staging area (index):** The proposed set of changes prepared for the next commit.
- **Commit:** A saved snapshot of staged changes with a message explaining the change.
- **Branch:** An independent line of development used to isolate work.
- **`main`:** The repository's primary branch; work should normally reach it through pull requests.
- **Pull request (PR):** A request to review and merge changes from one branch into another.
- **Draft pull request:** A PR marked as not yet ready for final review or merging.
- **`git status`:** Shows the current branch and the state of changed, staged, and untracked files.
- **`git diff`:** Displays unstaged changes; `git diff --staged` displays staged changes.
- **`git add`:** Places selected changes into the staging area.
- **`git commit`:** Creates a commit from staged changes.
- **`git push`:** Uploads local commits to a remote repository.
- **`git pull`:** Fetches remote changes and integrates them into the current local branch.
- **Tracking branch:** A local branch configured to follow a corresponding remote branch.
- **`origin`:** The conventional default name for the remote repository cloned from GitHub.
- **Commit history:** The ordered record of commits that explains how the project changed.

## Week 1 workflow reminder

1. Create a feature branch; do not commit directly to `main`.
2. Make a small, focused change in `stargazers-log`.
3. Run `git status` and `git diff` to inspect the work.
4. Stage the intended files with `git add`.
5. Create a clear commit with `git commit`.
6. Push the branch with tracking enabled: `git push -u origin <branch-name>`.
7. Open a draft pull request and save the PR, commit, and workflow evidence.
